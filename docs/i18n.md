# I18n

How UI strings are stored, named and checked. The app has two dictionaries:
[`translations.en.ts`](../src/lib/translations.en.ts) and
[`translations.ru.ts`](../src/lib/translations.ru.ts), exposed through
`useTranslation()` / `t('key')`.

## Overview

- Keys are flat strings with a **domain prefix**: `common.dashboard`,
  `dnd.classFighter`, `dh.homeWorld`, `admin.searchPlaceholder`.
- One key per user-visible string; both languages must contain the same keys
  and non-empty values.
- Components must not hardcode user-visible text: use `t('key')` for JSX text,
  `placeholder`, `title`, `aria-label` and `alt`.
- Proper names (`D&D`, `Dark Heresy`, `Scintilla`), units (`pt`, `ft`) and
  symbol-only values are exceptions, not translation gaps.

## Domains

| Domain | Area |
| --- | --- |
| `common.*` | shared dashboard, sheet labels, actions, fields |
| `auth.*` | login, registration, recovery, session |
| `admin.*` | `/admin` UI and API errors |
| `dnd.*` | D&D 5e sheet/form/data labels |
| `dh.*` | Dark Heresy sheet/form/data labels |
| `settings.*` | `/settings` profile and display controls |
| `demo.*` | guest landing and `/demo` |
| `io.*` | export/import UI |

Examples:

```text
common.notes
dnd.classFighter
dh.homeWorld
admin.searchPlaceholder
auth.passwordPlaceholder
io.exportSheet
```

Keys are physically grouped by domain with section comments. New keys go
**next to the feature block they belong to**, not into a random
tail. Use a short comment banner when adding a new block. Do not rename existing
keys in the same change as a feature fix.

## Level 1 and remaining exceptions

Level 1 renamed 1127 UI/data-label keys to dotted domain keys. Two transition
points remain and are tracked in the private backlog (level 2):

1. **55 sentence keys** from `DIVINATIONS`/effects are still unprefixed. They
   are values stored in character data (`divination`, `divinationEffect`), so
   changing them requires a data migration.
2. **Suffix fallback** in `language-context.tsx`: if a key is not found and has
   no dot, `t()` tries a unique `*.key` match. This keeps persisted data fields
   and server enums working during the transition. Level 2 updates those call
   sites and removes the fallback.

Do not add new unprefixed keys. The namespace test fails on new camelCase keys
without a domain.

## Rules

1. Add the same key to both dictionaries.
2. Keep `{placeholders}` unchanged in every language.
3. Translate RU values; only proper names and technical values may match EN.
   The current allowlist is in `tests/unit/translations.test.ts`.
4. Do not mix Cyrillic and Latin inside one word.
5. Do not bypass `t()`: JSX text and `placeholder`/`title`/`aria-label`/`alt`
   are checked statically.
6. Remove dead keys when a feature is deleted; don't leave stale blocks.

## Tests

- [`tests/unit/translations.test.ts`](../tests/unit/translations.test.ts) —
  key parity, literal `t('key')` coverage, namespaced keys and `t()` literals,
  empty values, duplicate keys, mixed scripts, and RU values that accidentally
  equal EN.
- [`tests/unit/i18n-hardcoded.test.ts`](../tests/unit/i18n-hardcoded.test.ts) —
  scans `.tsx` for JSX text and `placeholder` / `title` / `aria-label` / `alt`
  that bypass `t()`.

Known limitation: dynamic keys (`t(variable)`, `HOME_WORLD_KEYS[...]`, template
keys) cannot be verified statically; they rely on the mapping objects, the
suffix fallback during level 1, and manual review. Orphan-key reports are noisy
for the same reason, so they are not a failing test.

## Future namespacing

A deeper `domain.area.entity` hierarchy (`admin.users.search.placeholder`,
`dnd.data.class.fighter`) and removal of the 55 sentence-key exceptions and the
suffix fallback are a separate level 2 codemod. See the private `_BACKLOG.md`.
